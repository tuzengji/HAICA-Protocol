# AI协作能力测评协议

Human–AI Collaboration Assessment Protocol，简称 **HAICA Protocol**。当前版本为 **V2.1**，新任务包使用 `protocol_version = "2.1"`。

HAICA Protocol 规定任务怎么写、交付物怎么提交、结果怎么评分和保存。

## V2.1：整轮最佳实践反馈

题目可在私有 `tests/best-practice.json` 中声明最佳实践。收卷后额外用一个独立 DeepSeek Flash / max Harness 会话检查整套已配置题目，给出已体现、部分体现、未观察到或不适用，以及可定位证据。只对适用但未充分体现的做法给简短、可执行的分点建议，不改变任何任务分数或元能力分数。

标准和配置开考冻结，不加入题面或考生作答文件；接受同等有效的方法，区分用户行为与Agent自行行动。没有配置则跳过，采集或模型故障记录独立技术失败，含首次最多三次尝试，旧评测不回填。[字段与反馈规则](HAICA-Protocol.md#整轮最佳实践反馈v21)。

## 沿用 V2.0：整轮五维元能力评测

在原任务评分之外，给学习能力、任务编排与执行力、判断与决策能力、成果交付能力和创造力分别生成0—5分或N/A。五维不合并成新总分。

结果侧把每个最小计分项的实际贡献映射到五维，以各维满分容量归一化；题目占比从容量自动导出。轨迹侧只看人的指令、追问、选择、纠偏和验收，3为合格基线，高低分须有正负证据；无人的行为证据为N/A，详细档位锚点尚未固化。

学习、编排执行、判断默认结果60%／轨迹40%，交付、创造默认结果30%／轨迹70%。无轨迹证据时保留结果侧，但相应综合分为N/A。原产物评分、提交、连续计时和归档后释放沙盒规则保持。字段和公式见[整轮元能力评测](HAICA-Protocol.md#整轮元能力评测v21)。

## 沿用 V1.5：两层 rubric，同一产物合并判卷

评分只有两层：顶层 `rubric` 和其下可选的子 rubric（`scoring.components`）。**每条顶层 rubric 只对应一个待评产物，由一个 LLM 请求或一个 Agent 会话评完全部子项。** 子项继承同一产物和判卷器，逐项保留档位、理由和证据。

- `kind = "llm"`、`plugin_api = "llm/v1"`：一次请求提供完整输入，直接返回全部子项判定。能够直接阅读冻结文档、表格或图像判断的要求优先使用 LLM。
- `kind = "agent"`、`plugin_api = "agent/v1"`：一个 DeepSeek Harness 会话使用只读工具分步核对证据，返回全部子项判定。

多个视图仍属于同一个产物；原有文件集和目录也按声明的产物 ID 识别。私有参考基准不是额外的待评产物。`scoring.groups` 只是算分权重标签，不增加评分层级或模型调用。

后台脚本自动调度、校验、重试和汇总，不需要另一个 Agent 调度。失败以顶层 rubric 为单位重试，最多三次尝试；不拼接不同尝试、不挑高分，成功项不重跑。子项缺失或评分故障不会被当作零分，最终无法完成时整题总分为 `null`。

## 初始分、加减分与提交规则

**每题有一个初始分 `aggregation.base_score`，省略时默认 0；初始分 + 所有加分项满分必须恰好等于 100。** 初始分须为有限数值，不另设下界；加分满分只累计顶层 rubric 的 `weight`，不重复累计子项。减分项的单项与合计最高扣分均不受 100 分限制，最终可以为负分。例如初始 40 分配 60 分加分项，或初始 100 分只设扣分项，均符合规则。

沿用 `weighted_sum/v1`，有至少一个参与评分的产物通过有效性检查并得到 `evaluated` 结果时，总分为初始分加上带符号的 rubric 贡献；所有评分产物均缺交或无效时总分为 0，未参与评分的可选附件不单独授予初始分。rubric 的 `direction = "add" | "deduct"` 省略时为 `add`；`additive_deductive/v1` 是兼容别名。`weighted_components/v1`、依赖上限、`score_gate` 以及最终 half-up 两位小数算法均不变。部分缺交依然按 `missing_policy` 将依赖项贡献归零；必要评分失败时总分仍为 `null`，不能把服务故障当成无效产物记 0 分。

合并调用不合并、删除或放宽具体要求。迁移任务时保留题面、资料、criterion、档位、方向、权重和门槛，另建修订并验证同一组判定的算术结果一致。脚本继续做准入校验、客观测量和算分，不代替 V1.5 模型判卷。

系统默认作答（Rollout）为 **DeepSeek V4.1 Flash / low + DeepSeek Harness**；两种判卷方式均为 **DeepSeek V4.1 Flash / max**。实际模型标识、请求参数和证据须留档；直接 LLM 不伪造 Harness 轨迹。

考生可在评测结束前修改并重新提交；结束时选定每题最后一次成功提交，后台自动评分。私有评分内容不会进入题面或作答工作空间。

新评测从首次进入工作空间开始连续计时，截止时刻固定；退出、关页、断网和重连均不暂停或延长，后台 Agent 与终端可继续运行至截止。到时自动冻结最后成功提交或缺交记录，备份工作空间与可获取轨迹，完成评分和归档校验后释放沙盒。未提交文件不会被自动猜选为评分产物；仍可主动提前结束。

### V1.0：建立完整的任务与评测合同

首版于2026年9月18日发布，确立以下规则：

- **任务包与权限：**统一 `instruction.md`、`task.toml`、私有 `tests/evaluation.toml` 及公开环境材料的职责。题面和作答空间不包含私有 rubric、参考答案和模型判卷提示。
- **交付与判卷：**声明文件、文件集或目录等产物及其格式、数量、容量和读取视图；支持 Python 判卷器与 DSH Agent Judge。每条 LLM rubric、每次重试使用独立会话，这项隔离要求在 V1.0 就已存在。
- **计分与失败语义：**每题满分100，按 `raw_score / scale_max × weight` 汇总，最终统一舍入；题目集另外设置题目权重。缺交、产物无效和判卷服务失败分别记录，必要评分失败时总分为 `null`。
- **生命周期与证据：**一次整题提交，成功后不能替换；云端在线计时、退出暂停，另支持 Windows 连续计时。冻结题包、产物和运行条件，保存哈希、判卷请求响应及可取得的 Agent 轨迹，完成归档校验后才能重置沙盒。

**2026年9月20日维护修订：**[`7958031`](https://github.com/tuzengji/HAICA-Protocol/commit/795803199fca1c47c2c70d45ecd291ace1610db2) 统一公开仓库、协议文件和示例检查脚本的连字符命名，并更新相应引用；不改变计分规则。

### V1.1：补齐大材料、提前结束和证据完整性

**2026年9月23日首发，相对 V1.0：**

- **提前结束：**允许平台开放“仍有题目缺交时结束整轮评测”。必须列出缺交题目及产物，由用户明确确认；服务端再次核对并整体关闭，记录 `reason="assessment_end"` 和 `finish_confirmation`，不能把工作空间文件自动当作交卷。
- **材料读取与预算：**新增 `max_cell_chars`；明确 XLSX 只读可见工作表，区分公式与已保存缓存。rubric 文字和参考预算由22万扩大到300万字符，完整输入包由32扩大到256 MiB，运行资料由64 MiB扩大到1 GiB；补充图像容量和导入时组合预算检查。
- **证据定位修正：**增加 `evidence_ref`、`locator_ref` 和文字分段定位，由平台补齐真实路径、哈希与引文，减少模型手写这些字段造成的错误。
- **记录完整性：**补充原生日志完成性核验、可复原的请求记录、图像去重和 `page-manifest.json`；记录不完整不能假装判卷成功。

**同日维护修订：**[`20ddb78`](https://github.com/tuzengji/HAICA-Protocol/commit/20ddb787b2cb96950d88e928ae13864ba043a35b) 将 `duration_minutes` 从单题时限改为“计入题库的时间额度”。所有题目额度求和形成整轮共用时间，考生自由分配；切题、提交和同轮重开不重置时间。既有评测仍用开始时冻结的计时条件。

**保留边界：**V1.1 仍采用一次成功提交制，仍支持 Linux 与 Windows；此时还没有结构化子 rubric。

### V1.2：修订提交、结束统一评分与结构化子项

**2026年9月24日首发，相对 V1.1：**

- **提交可修订：**结束前可以多次提交，每次成功提交保留不可变副本；失败不会覆盖上一成功版本。增加 `revision`、`previous_submission_id` 和 `selection_state`，区分候选、已替代和最终版本，并明确请求幂等规则。
- **评分时机修正：**整轮结束或总时间耗尽时，原子选定每题最后一次成功提交，再统一排队评分。全部题目已提交也可继续使用剩余时间；在途上传不能越过截止替换最终版本。
- **执行环境收敛：**新版只使用 Linux 云工作台和 `linux-office`，移除 Windows 桌面连接、提交与连续计时入口；旧环境标识只用于读取历史记录。
- **调整材料容量：**单文件上限50→200 MiB、单交付项128→512 MiB、页数40→200、文本20万→200万字符、表格2万→10万单元格，表格结构化字符上限20万→200万。单图默认值从4 MiB降为512 KiB，可声明的上限仍为4 MiB。增加提交前文本/表格预检和办公文件解压保护，超限时保留上一成功提交。
- **完整读取大证据：**材料拆成有序块，`read_evidence(all=true)` 每次返回一批和 `remaining`，必须读到零。允许会话压缩，但保留原始材料、请求响应及压缩事件，摘要不能代替原始证据。同步提高模型/工具调用、完整输入及轨迹预算。
- **结构化子项：**新增 `weighted_components/v1`，声明分组、子项、等级和依赖；当时由一个 DSH Agent 判定同一 rubric 内的全部子项，程序计算依赖上限、组内均值与权重，模型不直接决定总分。

**同日维护修订：**[`4178c61`](https://github.com/tuzengji/HAICA-Protocol/commit/4178c61282684f5ab439adbac7a2de6f44f00542) 补清历史结果与复评边界：原题包重判与使用新版规则比较评估分别记录；后者保存新旧版本、产物哈希、起止时间、逐项执行及重试，保留原成绩。

### V1.3：每个子项独立、全自动判卷

**2026年10月4日首发，相对 V1.2：**

- **判卷单位改到最小子项：**没有子项时独立评 rubric；存在 `scoring.components` 时，每个 component（包括零权重前提项）单独使用新的 Harness 进程、home 和 session。父 rubric 负责汇总，不能在一次会话中评完多个子项。
- **后台全自动：**评分脚本自动领取最终提交、展开计划、启动会话、校验结果、重试失败项、计算依赖与权重并归档，不需要人或另一个 Agent 逐次调度。新增子项执行与结果记录，报告标记 `one-component-per-session/v1`。
- **判卷器边界：**新版本计分由 Agent Judge 完成；脚本保留文件校验和确定性算分职责，历史 Python 题继续按原版本运行。沿用 V1.2 的结束前修订、最后成功提交及评分失败留空规则。
- **默认运行配置：**首发记录平台采用 DeepSeek V4.1 Flash / low 作答、Flash / max 判卷；要求保存实际出站参数、返回模型标识与配置哈希，不能只改展示名称或静默降级。这属于默认运行配置，不是新增题包评分层级。

### V1.4：可选加减方向与旧题兼容

**2026年10月8日首发，相对 V1.3 的最终维护规则：**

- **简化加减分入口：**沿用 `weighted_sum/v1`，让 `direction="add"|"deduct"` 成为可选标记，省略默认 `add`；保留 `additive_deductive/v1` 作为等价别名。纯加分题无需补字段或增设扣分项。初始分仍固定0，加分上限合计100、扣分不限、允许负分。
- **修清旧题兼容：**无方向标记的旧加权题保留原计分和哈希，旧公式题继续执行原公式，不能被误当作纯加分；新版不再接受新建 `formula/v1` 任务，历史公式与 Python 判卷器按原版本保留。
- **保持独立裁决：**仍采用 V1.3 的逐原子项 Harness 会话。同一父 rubric 的子项方向一致，需要混合加分和扣分时拆成不同 rubric；扣分标准明确缺陷程度，不自动反转原有正确性得分。

**同日维护修订：**[`40283a2`](https://github.com/tuzengji/HAICA-Protocol/commit/40283a2) 新增可选 `score_gate`。引用的其他无门槛加分项贡献之和须严格大于阈值，本项才计分；否则由程序把本项贡献归零，保留原始判定。Judge 不接收其他判定或门槛结果；禁止自引用、循环和链式依赖，未声明门槛的题包不变。

V1.4 的新增重点是**可选方向标记、兼容入口与得分门槛**；加减分本身已在 V1.3 的10月8日维护修订中加入。

### V1.5：两级、单产物、按顶层合并评测

**2026年10月8日首发，相对 V1.4：**

- **固定两层与单产物：**顶层 rubric 下可以有子 rubric，每条顶层只绑定一个已声明产物；子项继承同一产物和判卷器，可使用该产物多个视图。`scoring.groups` 是权重标签，不构成第三层。
- **区分 LLM 与 Agent：**`kind="llm" / llm/v1` 改为直接请求模型；新增 `kind="agent" / agent/v1` 表示 Harness 工具会话。能直接读取冻结材料判断的内容优先用 LLM，需要分步核对证据时使用 Agent。
- **按顶层执行与重试：**一个请求或会话完成一条顶层 rubric 的全部子项，保留逐项档位、理由和证据。失败以顶层为单位重试，含首次执行在内最多三次尝试；不得拼接不同尝试、挑选高分或重跑已成功项。报告按顶层评测单位记录调用及子项覆盖。
- **保留评分要求：**合并调用不减少、放宽或改写子项标准、权重、方向和门槛。脚本继续负责准入、客观测量与确定性算分，未新增独立 Python 计分类别。旧版本 `llm/v1` 仍按原来的 Harness 规则解释。

**2026年10月9日维护修订：**[`29fc7c2`](https://github.com/tuzengji/HAICA-Protocol/commit/29fc7c2b72f2b8e164c4c45ecedc70412c77f7fd) 加入初始分规则：

- `aggregation.base_score` 从固定0改为可配置的有限数值，省略仍默认0；必须精确满足 **初始分＋顶层加分 rubric 满分合计＝100**，子项和组内权重不重复累计。
- 扣分单项与总额仍不限于100，最终可以为负分；允许初始100分且只有扣分项，不另设初始分下界。
- 有至少一个有效评分产物才计入初始分；有效但 rubric 得0分仍可计入。全缺交或全部评分产物无效时总分为0，必要判卷失败仍为 `null`；初始分不参与 `score_gate` 来源贡献。
- 报告新增 `applied_base_score` 记录实际计入值，同时保留声明的 `base_score`。不改旧版约束，也不重写已经满足规则的零初始分题包或历史成绩。

**2026年10月9日维护修订：连续计时与到期自动收尾。**

- **计时修正：**新评测从 `first_workspace_entry` 起固定截止时刻，`mode="continuous"`、`pause_on_exit=false`。退出、关页、断网、心跳失效或重新进入均不停表、不补时；取消考生暂停能力，后台 Agent 和终端可继续运行到截止，主动提前结束仍保留。
- **到期处理：**无需考生保持在线，自动关闭作答并停止进程，冻结每题最后一次成功提交；缺交生成空清单。备份工作空间、可获取的 Agent 轨迹和模型证据，按正常规则评分、生成并验证归档，成功后才释放沙盒；必要步骤失败保留源资料。工作空间备份不等于提交，不自动猜选未提交文件评分。
- **兼容范围：**新建评测统一采用此计时方式，也适用于 V1.1/V1.2/V1.3/V1.4 题包；V1.1 仍一次提交，其他版本的提交与判卷规则保持。旧评测沿用冻结计时条件，题包、示例、编译哈希、历史成绩及已发布 Release 快照不改写。此处记录协议维护内容，框架部署与运行验证分别留证。


### V2.0：题目与轨迹共同评估五项元能力

**2026年10月9日，相对 V1.5：**

**2026年10月9日后续维护（[v2.0.1](https://github.com/tuzengji/HAICA-Protocol/releases/tag/v2.0.1)）：按《元能力评估方案与用户反馈》修订。**

- 用私有 `capability_mapping` 映射每个最小计分项，五维比例合计1；按原权重、分组和实际带符号贡献计算容量与实得。题目占比自动推导，不再手填，不额外乘题集权重。
- 五维改为0—5。轨迹直接分别判断五维，3为合格基线，高分须正证、低分须负证；无人的介入证据为N/A。首发15项固定档位不再用于新评测。
